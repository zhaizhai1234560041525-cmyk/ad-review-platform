# 广告宣传智能审核平台测试与上线核验报告

日期：2026-09-21
对象：观审广告审核平台（🌍）、Dify 广告海报审核闭环
代码仓库：https://github.com/zhaizhai1234560041525-cmyk/ad-review-platform

## 1. 结论

**本地业务闭环可行，前后端本地联调通过；公网部署尚未完成。**

已验证两条业务路径：
- 新建海报 → 生成 → 审核 → 风险修改 → 复审 → 通过后导出。
- 上传已有海报 → 识别与审核 → 通过后导出原图；发现风险则展示修改建议并拦截通过版下载。

上传模式不自动修改图片，需用户按建议修改后重新上传。两种模式不可混同。

本报告区分此前真实联调记录和本次复测。本次没有重新发起收费的模型、生图任务；通过持久任务记录、已有验收记录、下载接口及自动测试核验结果。不将历史结果表述为本次新运行。

## 2. 测试环境与职责

| 层级 | 实现 | 职责 |
|---|---|---|
| 前端 | HTML、CSS、JavaScript | 需求输入、图片上传与预览、进度、风险报告、历史任务及下载 |
| 后端 | Python HTTP 服务、SQLite、图片归档 | 保管应用密钥、请求校验、调用 Dify、保存任务与执行下载门禁 |
| 工作流 | 本机 Docker 中的 Dify | 分支调度、实际画面识别、法规审核、生成修改与复审 |
| 模型服务 | DeepSeek、APIMart | 文本判断、视觉识别与图像生成 |

前端经后端调用 Dify Service API 的 /v1/workflows/run，接收并展示工作流进度。Dify 负责可编排的审核业务流程，前端负责用户交互；仅部署静态页面不能替代 Dify 与后端。

## 5. 异常处理与已修复问题

- 初次联调因本机 Python 默认 CA 缺失导致图片归档失败；改用系统可信 CA，保持证书验证，重新联调通过。原失败任务保留。
- 严格解析审核结果；接口异常、提前断流、需要人工处理或未通过，不放行下载。
- 此前验证同一重复提交返回原任务；相同请求标识但输入变化返回 409；损坏图片返回 400。
- 上传图片限制 5MB、2000 万像素；校验格式与实际解码结果。
- 已修复快速切换文件的哈希竞态，并补充风险原因展示。
- 应用与模型密钥未放入前端或 GitHub；真实任务数据库和图片未上传。

完整上线仍需：
1. 确定可运行后端及 Dify 的服务器或托管环境。
2. 配置 HTTPS、外部访问地址与服务端密钥。
3. 增加访问控制、用户任务隔离、调用限额及持久存储保障。
4. 在公网环境重新执行生成、上传、风险拦截和下载验收。

## 7. 验收边界

本次结果证明既有样例的本地功能可行，不代表所有广告风险均能识别，也不代表多用户、安全、性能或公网可靠性验收通过。当前流程依据内嵌广告法文本；行业专项规则与需人工核实的事实不由这批测试覆盖。

未进行压力测试、长时间稳定性测试、多用户隔离测试或公网端到端测试。后续部署后须补测。
